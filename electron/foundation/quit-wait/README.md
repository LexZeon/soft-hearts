# 退出后马上再打开（I-182）

记录：`docs/claude/2026-11-22-i182-wait-for-quit.md`。

## 做什么

电脑忙时，点"退出"后窗口马上消失，但 Electron/Chromium 自己的收尾要几十秒（40 个低优先级重活压着时，从窗口消失到进程真正结束量到 97～125 秒）。Electron 在收尾**之前**就把单实例锁还了，所以这时再点开，新的会拿到锁、和还没走完的旧进程同时用一个配置目录（实测 Chromium 报缓存"拒绝访问"）；还在保存的那几秒里点开，则会交给正在退出的旧实例，看起来点了没反应。

现在：

- 拿着锁的实例一开始退出，就在自己的配置目录里写 `quitting.json`（进程号、时间、程序名、界面语言）。它自己不删，下一个拿到锁的实例删。
- 新开的进程读到标记、标记里的进程还活着（同一个程序、不超过 5 分钟）时：先悄悄等 1.5 秒；旧的走完就直接启动。还没走完：还回锁（哪怕 Electron 已经给了它），把自己的 Chromium 数据搬到临时文件夹（在就绪之前，所以从不碰配置目录），右下角出一个小提示"她在收拾，马上就好…"（英文界面："She is tidying up, back in a moment…"），旧进程一走就用同样的命令行重新开一个正常启动的进程，自己退出。等满 3 分钟还没走完，就说"她还没收拾完，等一下再点开吧。"然后放弃这次打开。
- 正在退出的实例收到第二次打开时不再重开窗口，也不再退一次。

## 文件

| 文件 | 内容 |
|---|---|
| `plan.ts` | 纯逻辑：标记的读写和校验、`planStartup`（启动 / 交给正在运行的 / 等）、`runStartupLock`、`waitForOldExit`、`tasklist` 输出解析。不引用 Electron |
| `knobs.ts` | 旋钮（等多久、多久看一次、标记多久算旧）和提示文字 |
| `electron/wiring/startup-wait-wiring.ts` | Electron 这边：`takeStartupLock`（main.ts 的单实例锁）、等待的进程（临时文件夹、小提示、重新启动）、写标记、`second-instance` |

## 守的规矩和测试

- 两个进程永远不同时用一个配置目录：旧进程活着时新的不启动；在等的那个在就绪前搬离配置目录。
- 进程号已死（崩溃留下的标记）、被别的程序重用、标记太旧，都不会让新开的去等。
- 只有拿着锁的实例写标记。
- 测试：`tests/quit-wait.test.ts`（假世界：旧实例从运行、退出、收尾到结束的每个时刻）、`tests/quit-wait-wiring.test.ts`（接线的真实代码配假 app）。变异：`scripts/dev/mutations/trunk.json` 里的 `I182-*`。

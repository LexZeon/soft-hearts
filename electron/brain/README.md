# 她的大脑（brain）

给别的 agent 看的部分说明。总入口见 handbook/for-other-agents.md；**想换成别的模型当她的大脑，先读那一页最后一节「换大脑要实现什么」**，逐处的 Claude 依赖在 handbook/brain-interface.md。

## 1. 这部分做什么

她怎么想、怎么回你：一轮聊天（你发一句，她流式回一句，带心情和小动作的尾注）、常驻的聊天进程（一段对话一个进程，首字快）、聊天的存档和关系（`CompanionService`，里面也有心情宿主）、聊天不可用时她说的那句、调度台（一句话涉及哪个模块）、停停说说（陪看时她插一句）、回复的节奏和首字计时、聊天里提的设置、她只管说话（I-098，实验开关）、I-134 长对话、I-139 提示词大改（开关）。

用户感觉到的是：她回得快、像她；你点停止她就停，不会过一会儿又冒出一句；换了角色或对话，旧的回复不会写进新的里。

## 2. 文件在哪

- 三个文件夹：`electron/brain/`、`shared/brain/`、`src/brain/`。
- 公开页：`electron/brain/index.ts`、`shared/brain/index.ts`、`src/brain/index.ts`。
- 陪伴聊天的进程：`electron/brain/claude.ts`（单次调用 `streamClaude`；**安全文件，大修期间一字不改**）、`electron/brain/claude-session.ts`（常驻聊天 `PersistentClaudeChat`；它的类型在 `claude-session-types.ts`，通话里留小画面的规矩在 `call-glances.ts`）、`electron/brain/session-pool/`（I-186：每个角色一个 `PersistentClaudeChat`，接线里的 `claudeChat` 就是它）。
- 起 Claude Code 进程的启动门（I-202）：`electron/brain/claude-start-gate.ts`；应用里每一条起 Claude Code 进程的路都经过它（清单在 `docs/claude/2026-11-23-claude-login-race.md`）。
- 起和结束 Claude Code 进程的工作线程（2026-11-24）：`electron/brain/claude-launch/`（`launchClaude`、`terminateClaude` 经它发 taskkill）。大脑里不许再直接用 Node 的子进程模块。
- 主机这边的接线（第 4h 步搬来）：
  - `electron/wiring/brain-wiring.ts`：`wireBrain(given)`（造聊天进程、调度台、停停说说、节奏、首字计时、出问题时的台词、聊天里的设置提议）；ready 链的 `startCompanion(...)`（造 `CompanionService` 并接上各部分的来源）、`attachChatWindows(pet, controls)`；三道关 `pending`、`launchTask`、`reserveCompanionAuthoring`；`core: ['companion', 'claude-chat', 'chat-turn']`（第 7 步的隔离永远不关）。
  - `electron/wiring/brain-chat-wiring.ts`：聊天一轮和它的取消（`registerChatTurn(ipc, needs)`，由大脑的 `register` 调）。单独一个文件，是因为合在一起约 63 KB，超过 40 KB 的线。
- 别的部分读的状态是 `brain-wiring.ts` 的活绑定：`companion`、`claudeChat`、`chatOutage`、`moduleRouter`、`pauseTalk`、`replyRhythm`、`replyLatency`、`chatSettings`、`pending`、`LONG_CHAT`、`SPEAK_ONLY_ON`、`i139Chat`。
- 窗口这边：`src/wiring/chat-wiring.ts`、`src/wiring/chat-view-wiring.ts`（`src/main.ts` 拆分后）。接口切片 `shared/brain/desktop-api.ts`；体验记录切片 `shared/brain/journal-entries.ts`。
- 留在 `electron/main.ts` 的（第 4h 步记录写了理由）：建窗口和回复窗口、`windowEvents`（关掉的窗口在那里中止它在 `pending` 里的任务）、ready 链和退出的顺序（退出时等 `pending` 里的聊天、关聊天进程）、`publishCue`（主动的认领）、`chatActions` / `playChatAction`（归属留给第 5 步）、`syncCharacter` 和语言研究（角色卡的）、`savedCompanionContext`（三行，金标准钉着 saveSettings 的 43 步）。

## 3. 从哪进、谁调用它

- main.ts 在原来造聊天进程的位置调用 `wireBrain(...)`（声音之后：聊天进程的计时用语音通话的）。
- `brainPart.register(partIpc('brain'))` 在录制器里，注册的有：聊天一轮和取消、聊天设置的选择、最近的聊天、新对话、试听、Claude 可用性四个、I-134 开场白、模型别名。
- 语音通话和语音聊天经 `electron/voice/voice-chat-host.ts` 用同一个常驻进程（`ports.claude.stream`）。

## 4. 它守着的规矩

- **回复文字什么时候停了，记下来（2026-11-24，`electron/brain/stream-gaps.ts`，`docs/claude/2026-11-24-voice-gaps.md`）**：每条回复在 `companion.ts` 里量两个最大的间隔，一个是模型原始的字到主进程的，一个是经过协议和强调过滤后送出去（给气泡和存档）的，各记在第几个字、当时在等什么（封闭的词），写成一行 `stream-gaps`；没有文字。原始间隔大而送出的间隔不比它大，就是模型那边停了；送出的间隔更大，就是中间扣住了。首字行（`first-char`）在是定时器收尾写的时候多一个 `endedBy: 'settle-timeout'`（回复结束约 15 秒后才写的行，毫秒数不受影响）。

- **起进程、结束进程都不占主线程（2026-11-24，`electron/brain/claude-launch/`，记录 `docs/claude/2026-11-23-unbound-step6.md` 末节）**：大脑起的每个 Claude Code 进程（常驻聊天进程、备用进程、单次调用）都由一个工作线程起，结束时也由它发 taskkill /T /F（还没关就再 kill，和以前一样）；主线程只发消息，进程的输出按原来的顺序回来。以前在主线程同步起，一次卡 30～660 ms，她的窗口同样长度不出帧。**换假 Claude 只有一个口**：`launchClaude` 先问 `globalThis.__softHeartsClaudeLaunch`（冒烟、预试用、长时间测试从外面装上，封住；预试用真 Claude 模式只计数）；单元测试照旧用 `ClaudeProcessOptions.spawn`。主线程自己的 `spawn` 在冒烟里拒绝一切 Claude 启动。退出时第一步多等工作线程把 taskkill 都发出去（3 秒内）。测试：`tests/claude-launch-off-main.test.ts`（含大脑里除了工作线程的程序文字，没人提子进程模块）；变异 `S6-*`（4 条）。**起来闸**（同日，同一记录「退出后才起来的进程不再收到请求」）：拿到进程对象时进程可能还不存在；写给它的东西压在主线程，工作线程说起来了才发，之前被结束（terminate / kill）就全扔——主人在它起来前放手（退出、取消预热、换角色、停下单次调用），它起来就被关，什么都没收到。新代码可以照常一拿到就写，不用自己等。测试 `tests/claude-launch-up-gate.test.ts`，变异 `UPGATE-*`。
- **不带父 Claude Code 会话的连接（2026-11-25，`electron/brain/claude-env.ts`、规则 `shared/brain/claude-session-env.ts`，`docs/claude/2026-11-25-claude-env-from-session.md`）**：软件起的每个 Claude Code 进程（聊天、常驻、备用、haiku 小调用、助手、任务执行、`claude mcp add/list`、`claude --version`）的环境都出自 `claudeEnvironment`：去掉父会话的 `CLAUDE*` 变量（只留用户自己的登录和提供方选择）和 `ELECTRON_RUN_AS_NODE`；软件本身是从 Claude Code 会话里打开的（环境里有 `CLAUDECODE`、`CLAUDE_CODE_ENTRYPOINT` 等标记）时，还去掉那个会话的地址和凭据变量（`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_API_KEY`、`ANTHROPIC_CUSTOM_HEADERS`、`CLAUDE_CODE_OAUTH_TOKEN` 等），没有标记时保留。去掉了在体验记录记一行名字（`claude-env-dropped`，每次运行一行，从不记值）。发现 `claude` 时不选 Claude 桌面应用自带的那份（`scripts/claude-discovery.mjs` 的 `desktop-bundled`），「连接」的提示说清楚要装官方 Claude Code 并登录一次。测试：`tests/claude-env-from-session.test.ts`（含一张列出每个起进程位置的表，新加的起进程的文件不在表里就失败）、`tests/claude-env-launch.test.ts`（`scripts/setup.ps1` 的启动卫生）；变异 `ENV-1`～`ENV-10`。
- **熟悉度变了不重开她的进程（2026-11-26，`claude-session.ts`，`docs/claude/2026-11-25-first-turn-empty.md`）**：常驻进程的钥匙只有对话、人设、模型；关系那几句的标签（`openingKey`：慢慢熟悉开关、级别、昵称）不在里面。标签变了（I-210 之后第一天第 3 轮就会升级）那一句把新的关系那几句带上，只带一次（`relationTag`）。测试 `tests/claude-session-reuse.test.ts`（标签用熟悉度模块真算）、`tests/claude-session.test.ts`；变异 `FT1`、`FT2`。

- **聊天一轮里的每个"过期就不写"都有用**：读之前先确认这一轮还是当前的（生成号、角色卡、范围、对话）。加新的写回（记忆、心情、语音上下文），也要先过同样的判断，并把它写进 `scripts/dev/mutations/brain.json`。
- **`prompt` 和 `imageDataUrls` 是 getter**，写进进程那一刻才读：被删的记忆、过期的画面不能带出去。别改成先算好再传。
- **`brain-chat-wiring.ts` 已经 33 KB**：新逻辑放进 `electron/brain/` 的模块，聊天一轮里只留调用。
